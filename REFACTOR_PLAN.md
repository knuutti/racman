# SluMAN Sly 2 & Sly 3 Refactoring Plan

## Background

This plan was generated by analysing all shared, duplicated, and poorly structured code patterns across the Sly 2 and Sly 3 implementations. The relevant files are:

- `RaCTrainer/SLY2/SLY2Speedrun.cs`
- `RaCTrainer/SLY2/Sly2Practice.cs`
- `RaCTrainer/SLY2/Sly2Gadgets.cs`
- `RaCTrainer/SLY3/SLY3Speedrun.cs`
- `RaCTrainer/SLY3/SLY3Form.cs`
- `RaCTrainer/SLY3/SLY3GadgetsForm.cs`
- `RaCTrainer/offsets/SLY2/sly2.cs`
- `RaCTrainer/offsets/SLY3/sly3.cs`

---

## Architectural Constraints

Three constraints shape the entire plan and must be understood before starting:

### 1. WinForms Designer + abstract base forms
An `abstract class Base : Form` compiles and runs fine, but Visual Studio's Designer refuses to open concrete child forms that inherit from a non-trivial base. The workaround: all shared **logic** goes in the base class, all **controls** stay in the concrete `.Designer.cs` files. Concrete handler methods (wired by the Designer) call protected base methods. Never move `InitializeComponent` into a base class.

### 2. `sly2.addr` mutable static field
`public static Sly2Addresses addr` is declared at class level but overwritten in the constructor (`sly2.cs:264` + `:296`). If two `sly2` instances existed, the second would silently corrupt the first. Fix: make it an instance field. The only external caller is `Sly2Gadgets.cs` (lines 164–176), which uses `sly2.addr.X` statically — update those to `game.addr.X`. Gets its own isolated PR.

### 3. `using static racman.SLY3Speedrun` in `SLY2Speedrun.cs`
`SLY2Speedrun.cs` line 10 imports Sly 3's Speedrun class statically, solely to borrow the `RunFileData` inner class. Removed once `RunFileData` moves to `RunFileLoader` (Step 4).

### Step 3 — GROUP B: Create `SlyGameBase`

**Create**: `RaCTrainer/offsets/SlyGameBase.cs`  
**Modify**: `sly2.cs`, `sly3.cs`  
**Also**: Add `<Compile Include="offsets\SlyGameBase.cs" />` to `RaCTrainer.csproj`

Change `sly2` and `sly3` inheritance from `: IGame, IAutosplitterAvailable` to `: SlyGameBase, IAutosplitterAvailable`.

`SlyGameBase` exposes abstract address properties that each subclass implements as `=> addr.X`:

```csharp
public abstract class SlyGameBase : IGame
{
    protected SlyGameBase(IPS3API api) : base(api) { }

    protected abstract uint AddrInputOffset { get; }
    protected abstract uint AddrFmvState { get; }
    protected abstract uint AddrDialogueState { get; }
    protected abstract uint AddrDialogueFrameCounter { get; }
    protected abstract uint AddrMapAOB { get; }
    protected abstract uint AddrCurrentJobId { get; }
    protected abstract uint AddrCurrentCheckpointId { get; }
    protected abstract uint AddrActiveCharacterPtr { get; }
    protected abstract uint AddrTransformOffset { get; }
    protected abstract uint AddrCoordsOffsetX { get; }
    protected abstract string CurrentMapIndicator { get; }  // => maps[mapIndex].indicator
}
```

Methods moved into `SlyGameBase`:

| Method | Notes |
|---|---|
| `ConvertSlyButtonsToStandardFormat` | Identical 16-line bit-map in both games |
| `SetupInputDisplayMemorySubsButtons` | Uses `AddrInputOffset`; calls the above |
| `WriteMemoryRegion` | 256-byte chunk-write loop |
| `SetMapName` | Clear 64 bytes + write ASCII |
| `SetCurrentJob` (elevate to `protected`) | Write jobId, checkpointId, checkpointId+4 |
| `SkipCinematic` | Uses `AddrFmvState`, `AddrDialogueFrameCounter`, `AddrDialogueState` |
| `GetPlayerCoordsAddress` (keep `private`) | Pointer chain via `AddrActiveCharacterPtr` + `AddrTransformOffset` |
| `SavePosition` / `LoadPosition` | Uses `GetPlayerCoordsAddress` + `CurrentMapIndicator` |

**Risk**: Medium. Most structurally invasive single step. Mitigation: abstract address properties keep the base decoupled from concrete `addr` objects.

### Step 4 — GROUP C: Create `RunFileLoader`

**Create**: `RaCTrainer/RunFileLoader.cs`  
**Modify**: `SLY2Speedrun.cs`, `SLY3Speedrun.cs`, `Sly2Gadgets.cs`, `SLY3GadgetsForm.cs`  
**Also**: Add `<Compile Include="RunFileLoader.cs" />` to `RaCTrainer.csproj`

```csharp
public class RunFileLoader
{
    // configFile: e.g. "data/s2_run_file_config.txt"
    // gadgetKeyPrefix: "Sly2" for S2 (yields "_Sly2GadgetUnlocks"), "" for S3
    // episodeKeyMap: { "Episode 1" => "Episode1", "Episode 6 (CE)" => "Episode6_CE", ... }
    public RunFileLoader(string configFile, string gadgetKeyPrefix,
                         Dictionary<string, string> episodeKeyMap) { }

    public string GetEpisodeKey(string episodeName) { }
    public RunFileData LoadRunFileDataFromConfig(string episodeKey,
        Func<string, (uint startAddress, uint size)> fallbackRegion) { }
    public (byte[] gadgetBytes, byte[] bindingBytes) LoadRunFileGadgets(
        string episodeKey, bool useFallback = false) { }

    public class RunFileData
    {
        public string MapName { get; set; }
        public uint SpawnLocation { get; set; }
        public byte[] MemoryData { get; set; }
        public uint MemoryStartAddress { get; set; }
        public float SuckValue { get; set; } = 0.0f;
    }
}
```

Parameterisation of differences between Sly 2 and Sly 3:

| Difference | Solution |
|---|---|
| Config file name | Constructor `configFile` param |
| Gadget key suffix (`_Sly2GadgetUnlocks` vs `_GadgetUnlocks`) | Constructor `gadgetKeyPrefix` param |
| Episode set (8 for S2 vs 7 + CE variants for S3) | Constructor `episodeKeyMap` dict |
| Sly 2 fallback to data config in `LoadRunFileGadgets` | `bool useFallback` param |

What to **delete** from each consumer:

| Consumer | Delete |
|---|---|
| `SLY2Speedrun.cs` | `RunFileData`, `GetEpisodeKey`, `LoadRunFileDataFromConfig`, `LoadRunFileGadgets` body, `StringToByteArray`, `ConvertMemoryDataString`, line 10 (`using static racman.SLY3Speedrun`) — **F8** |
| `SLY3Speedrun.cs` | Same set |
| `Sly2Gadgets.cs` | `GetEpisodeKey` |
| `SLY3GadgetsForm.cs` | `GetEpisodeKey` |

Sly 3's `LoadCompleteRunFile` extra logic (`SetSuckValue`, Episode 6 CE/NoCE branching, `SetTutorialComplete`) stays in `SLY3Speedrun.cs` — those are form-level concerns that consume `RunFileData`.

**Risk**: Medium. Config key formats must be preserved exactly. Verify both Sly 2 and Sly 3 paths after the change.

// All controls remain in concrete .Designer.cs files.

    protected class GadgetInfo { public int UnlockBitIndex; public int? ButtonBindingIndex; }

    // All shared methods live here verbatim
    protected bool GetBit(byte[] bytes, int bitIndex) { }
    protected void SetBit(byte[] bytes, int bitIndex, bool state) { }
    private List<string> GetCheckedGadgetNames(CheckedListBox list) { }
    private void PopulateComboBox(ComboBox box, List<string> names) { }
    private string FindGadgetByBindingIndex(int index) { }
    protected byte[] GetCurrentBindingBytes() { }
    private void SuspendComboBoxUpdates() { }
    private void ResumeComboBoxUpdates() { }
    private void LoadGadgetsToList(CheckedListBox list, byte[] bytes) { }
    private void LoadBindingToComboBox(ComboBox box, uint baseAddr, int offset) { }
    private void PopulateSlyBindingComboBoxes() { }
    private void PopulateBentleyBindingComboBoxes() { }
    private void PopulateMurrayBindingComboBoxes() { }
    protected void PopulateBindingComboBoxes() { }
    protected void LoadGadgetBindings() { }

    // Virtual — Sly 3 overrides to add attack-level logic
    protected virtual byte[] GetCurrentGadgetBytes() { }
    protected virtual void SaveGadgets()
        => game.SetGadgetUnlocks(GetCurrentGadgetBytes());
    public virtual void LoadGadgets() { }

    // Sly 3 overrides to also write _SpecialAttacks key
    protected virtual void SaveGadgetsToRunFile() { }

    // Shared handlers (Designer-wired handlers in subclass call these)
    protected void HandleSaveButton() { }
    protected void HandleSaveAndReloadButton() { }
    protected void HandleSaveRunFileGadgets() { }

Sly 3 overrides in `SLY3GadgetsForm`:
- `GetCurrentGadgetBytes()` — adds spin/push/jump attack level logic
- `LoadGadgets()` — calls `base.LoadGadgets()` then `LoadSpecialMoveLevels(...)`
- `SaveGadgetsToRunFile()` — calls base then writes `episodeKey + "_SpecialAttacks"`

Sly 2 override in `Sly2Gadgets`:
- `ExtraGadgetLists` — returns `vaultGadgetsCheckedList`

**Risk**: Highest of all steps. Mitigation: abstract-property pattern for every Designer control referenced in base logic. Document Designer limitation in a comment on the class.
